# 910 工程约定（Conventions）

> 干活的纪律。新增约定先改本文件再写代码。

## 1. 文档纪律（继承自本方仓库的既有实践）

- **编号文档按序阅读**：每篇只依赖前面的篇目；新概念先进 001 术语表再进正文。
- **裂缝编号**：每个 bug/设计缺陷修好后，在对应文档记"裂缝 N：症状→根因→修复→防复发"，跨文档用 `[C-N]` 引用。不许删历史裂缝条目。
- **公告版本化**：里程碑完成后在 `docs/announcements/` 写发布说明（学 Word体系公告格式：版本/日期/状态/核心升级/兼容性）。
- **文档先于代码**：新机制必须有 ADR 或编号文档先行；文档与实现冲突时以文档评审结论为准。

## 2. 代码纪律

- **core 零 I/O**：`core/` 不碰文件系统/网络/时钟——时间由注入的 `now()`，随机由注入的种子（对齐上游 core 纪律）。
- **一处状态一个写者**：信用/怒气=脊髓写，Ticket=Router 写，遥测=内核写（002 §7 表）。
- **白名单求值器**：任何"用户写条件表达式"的地方必须走 SafeEvaluator 模式（字段白名单+禁 eval），禁止裸 eval/new Function。
- **错误分类**：技术故障（重试）与安全拒绝（计入边界试探计数）分开报，绝不混成一句"工具失败"（继承 HooH SEC-017/MCP 503/504 分档）。
- **降级留痕**：可选增强静默降级时必须产生一条事件；安全边界（HooH/审计链/熔断）绝不静默降级。
- **事件指认生产者**：报错/记录必须指认真实来源，禁止只写症状（H-21）。

## 3. 移植件对拍

- 每个 TS 移植件文件头注明：`origin: <原件仓库路径>@<commit/版本>` 与 `behavior-diff: <行为差异列表>`；
- P3 里程碑前完成一轮对拍：同输入表跑原件（Python）与移植件（TS），逐字段比对，差异要么修要么写进 behavior-diff。

## 4. 审计与回放

- 审计链哈希算法：HMAC-SHA256，密钥在项目外（继承 HooH signing_key 惯例）；链头哈希每周快照到只读位置。
- 任何"看起来像状态被绕过总线改了"的现象按 P0 级缺陷处理（对齐"Agent 自己可写审计状态=没有审计"）。
- 回放测试是 CI 的一部分；主分支上回放不一致直接红。

## 5. Git 与协作

- 分支：`main` 保护；工作分支 `p<N>-<topic>`；提交信息中文、动词开头、引用裂缝号或文档编号。
- 本仓库与上游 fork（`dsh-superagent-prototype`）互不 push；对照实验在 shepherd 仓库内跑，fork 只读。
- AI 产生的一切提交遵守 910；人类终审权（Word体系原则）适用于：ADR 接受、护栏参数变更、熔断解除、破坏性操作。

## 6. 测试纪律

- 测试运行器：**Node 内置 `node:test`**（`node --test --experimental-test-isolation=none`），不引入 vitest/jest。原因：vitest→vite→esbuild 链的 esbuild 服务是 stdio 管道子进程，在本项目当前运行环境的沙盒内受 EPERM 限制（2026-11-07 实测）；`node:test` 零第三方依赖、零 spawn，与 910 §2 的零构建脚本立场一致。沙盒限制解除后如需迁移再走 ADR。
- mock 回放优先：任何单测不得打真 API；
- 判分器与被测对象隔离：判分器只读总线与 blob，不读 Worker 自述；
- 每个基准剧本必须有判分断言，无断言剧本不许进 `mock-gen` 主目录。
