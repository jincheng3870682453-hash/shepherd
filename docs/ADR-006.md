# ADR-006 TypeScript 运行形态：strip-types 直跑及其约束

- 状态：已接受
- 日期：2026-11-08

## 背景

Shepherd 的测试与运行采用 Node 内置 test runner + `--experimental-strip-types`（ADR-004 关联：910 §6 的零依赖立场）。strip-only 模式**不做代码生成**，因此以下 TypeScript 语法不可用：

1. **参数属性**（`constructor(private x: T)`）—— 需要生成字段赋值代码。已四次撞墙（session 测试桩、pool、dual、github），每次都是运行时 SyntaxError 而非编译期发现。
2. `enum`（非 const）、命名空间、旧式装饰器 —— 同理需要生成。

另：`exactOptionalPropertyTypes: true` 下，可选属性赋 `undefined` 是类型错误（`x?: string` ≠ `x?: string | undefined`）——已三次触发（events、session、llm/deepseek）。

## 决策

1. **全仓禁用参数属性**：字段声明 + 构造函数显式赋值。类型检查器拦不住这个错（tsc 认为合法），必须靠纪律 + grep 检查：
   `grep -E 'constructor\s*\(\s*(private|public|protected|readonly)\s' src tests` 必须为空（进 CI）。
2. **可选属性统一写 `x?: T | undefined`**，赋值前判 undefined（不再写三成分支构造）。
3. `tsc --noEmit` 是编译闸门，但**不是运行形态的完整保证**——运行时语法约束只有 grep/CI 能拦。

## 后果

- 正面：保持零构建工具链（无 tsdown/esbuild）；代码显式化，构造注入一目了然。
- 负面：样板行数略增（每类 +2~4 行）；新贡献者可能不知道这条隐形约束——CI 兜底。
- 替代方案：引入 esbuild/tsc 转译构建（放弃：与 910 §6 零构建立场冲突，且沙盒内 esbuild 的管道 spawn 受限）。
