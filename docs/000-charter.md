# 000 立项章程（Charter）

> Shepherd：一个事件驱动的超智能体编排层原型。
> 状态：立项评审中（未开工写代码）。

## 0. 一句话

**为"一直在岗、并行推进、主动找活、出事自愈"的多 Agent 舰队造编排层**——入口过滤与出口裁决两端复用既有轮子（jcf / HooH·互），中间这一层自己焊。

## 1. 论点（要证明什么）

用一组实验证明下面这个论点成立，而不是做一个产品：

> 当执行环境的入口（过滤/信用）与出口（裁决/快照/回滚）都已有确定性边界时，
> 一个事件驱动的编排层（Router/Worker 双层 + 异步会话内核 + 外部 Watchdog）
> 能让多个复杂任务在最少的人类注意力下并行推进，
> 且其监督机制（皮层提议→脊髓裁决）的误杀率与漏放率可以被测量、被调参、被信用函数自适应。

## 2. 背景：为什么是现在

- DeepSeek 于 2026-10-31 公开《Super-agent：迈向更自主的 Agent 系统》架构文章，并开源原型 `dsh-superagent-prototype`（已 fork：`jincheng3870682453-hash/dsh-superagent-prototype`）。
- 该原型已实现：双层架构、两级事件过滤、订阅直通、效果队列、SQLite 持久化、Web 面板。
- 该原型**未实现**（= 我们的空白区）：外部 Watchdog、投机执行、异步 ReAct 全双工、存算分离、链式召回完整形态。
- 本项目的既有机件（先于该文章独立完成）：
  - `jcf`（jinchen-halfdup）：入口过滤管线、模糊度三路分流、用户信用体系 v2.1、HMAC 审计链、怒气衰减状态机、SafeEvaluator；
  - `HooH·互`（ace）：出口裁决链、写前快照/回滚、沙箱（Job Object/Docker）、安全事件分级告警、MCP 包；
  - `Word体系`（aitoolkit）：诱饵后验（BaitPool + AST 签名）、物理快照、统一网关、启动健康检查；
  - `Archive.py`：SimHash 主题检测、回忆快照注入、urgency 信号（其原始需求文档即 DeepSeek 记忆方案 V1.7）。

## 3. 范围

### 做（v1 原型）

1. **事件总线**：持久化、幂等、因果链、可回放（ADR-001）。
2. **异步会话内核**：`start()/stop()` 异步工具、结果步间注入、取消竞态、上下文归档（乐观执行分级见 ADR-003）。
3. **Router/Worker 双层**：Router 轻模型只分派，Worker 隔离会话干活；订阅直通照抄上游设计。
4. **外部 Watchdog**（旗舰特性一）：结构化遥测→脊髓规则→皮层模型判断→分级介入；介入额度用怒气衰减状态机；阈值被信用函数缩放。
5. **信用 × 诱饵**（旗舰特性二）：Worker/信息源信用档案；诱饵后验作为"报告为真"的锚点；信用决定 Watchdog 灵敏度与投机预算。
6. **投机执行**：带预算的后台任务，双通道触发（显式规则 + 评估模型提议），交付门槛=诱饵/复现验证，丢弃进 would-do 日志出命中率仪表盘。
7. **事件源**：GitHub 轮询源（v1 真实）+ 本地模拟源（压测用）；事件 schema 见 005。
8. **成本护栏与基准试验台**：分电表/总闸/熔断；注入故障的临床试验（006）。

### 不做（v1 非目标）

- 不做产品化 UI（一个最简面板/CLI 看板即可）；
- 不做 Router 水平切分（上游自己也说为时过早）；
- 不做存算分离的跨机部署（v1 同机双进程、纯协议隔离，协议设计预留跨机）；
- 不做多实例 A2A；
- 不接飞书/IM（上游原型已有飞书源可日后移植；v1 用 GitHub + 模拟源足够）；
- 不改 HooH / jcf / aitoolkit 既有代码——只在 shepherd 内移植纯算法逻辑（ADR-004）。

## 4. 成功判据（原型阶段的"毕业条件"）

1. 基准试验台可重复运行：同一注入故障场景跑 N 次，出误杀率/漏放率/恢复时间/成本四张表；
2. 对照实验完成：双层+Watchdog+信用 vs 上游单 Session+Subagent 方案 vs 无 Watchdog 裸奔，三类各 5 次；
3. 至少一次"自愈闭环"真实发生：注入死循环/偏题故障 → Watchdog 自动介入 → Worker 重启 → 任务最终交付，全程事件可回放；
4. 投机执行命中率有数字：至少 20 个投机机会的 would-do/交付/丢弃统计；
5. 全部介入动作 100% 进审计链（HMAC），抽查可回放。

## 5. 风险登记

| # | 风险 | 应对 |
|---|------|------|
| R1 | Watchdog 误杀深任务 | 快照回滚使"杀"可逆；信用缩放阈值偏保守；介入额度+升级给人 |
| R2 | 监督链被提示注入 | Watchdog 只吃结构化遥测与 HooH 裁决记录，不吃自由文本（003 §4） |
| R3 | 成本失控 | 每会话分电表+全局总闸+熔断（006 §2）；Router/评估用便宜档 |
| R4 | 事件语义漏洞导致状态错乱 | 幂等键+因果链+全序强制（005 §2）；回放调试纳入验收 |
| R5 | 上游原型/API 变化破坏对照 | fork 已固化基线（commit 8c32a9d）；对照实验锁版本跑 |
| R6 | 范围蔓延（本仓库历史高发） | 007 路线图每期有"砍到什么程度仍成立"的退路；新增机制必须先补 ADR |
| R7 | 跨语言集成（Python 生态 vs TS 内核） | 边界只留协议：HooH-MCP 不动；纯算法移植 TS（ADR-004） |

## 6. 角色

- 人类：立项决策、评审文档、终审权（对齐 Word体系"人类的终审权"原则）、破坏性操作授权。
- 本会话（AI）：架构定稿、编码、测试、基准运行、报告。
- HooH：出口裁决与快照（不认识 Shepherd，只认协议）。
- jcf 移植件：入口过滤与信用（进内核热路径）。
